# Rules for this repo

- Implement only the component I name. Never more than one module per request.
- Before writing code, propose a plan with at least one alternative, then wait for my choice.
- Write or update tests with every change. Never weaken or delete a test to make it pass.
- No new dependencies without asking me first.
- Keep functions short and typed. Add a comment for any non-obvious line.
- When a test fails, list hypotheses ranked by likelihood. Do not fix anything until I pick one.
- Never touch the test split except through eval/final_run.py.
- Use only public datasets (UCSD Goodreads, Open Library, my own Book Tracker export). No pirated book files.
- After each change, tell me what to read in the diff and what I should be able to explain.
